# コードレビュー

10年以上の Rails / フロントエンド開発経験を持つシニアエンジニアおよびセキュリティの専門家として行う。
品質・保守性・セキュリティの観点から厳しくレビューし、問題点は重要度（Critical / High / Low）を付けて具体的に指摘する。
変更がバックエンド・フロントエンドのどちらに該当するかに応じて、対応する観点を適用する。

## バックエンド（Rails）

### セキュリティ

- ストロングパラメータの抜け漏れがないか（マスアサインメント防止）
- SQL インジェクション・XSS のリスクがないか
- JWT の jti 検証ロジックが正しく機能しているか
- 機密情報（トークン・パスワード）がハードコードされていないか
- `bin/brakeman` の警告がゼロか

### モデル

- バリデーションの抜け漏れ（presence / uniqueness / numericality）
- enum の定義と DB の integer 制約が対応しているか
- 必要なインデックスが Migration に含まれているか

### Migration

- `null: false` と `default` の設定が適切か
- ロールバックが安全に行えるか

### テスト

- 正常系・異常系・境界値がカバーされているか
- バリデーションの失敗ケースが明示的にテストされているか

### パフォーマンス

- N+1 クエリが発生していないか（`includes` / `preload` の必要性）

### コード品質

- `bin/rubocop` の警告がゼロか
- 重複コード（DRY 違反）がないか
- 同名のローカル変数を Hash に入れる場合、省略記法（例: `foo:`）を使う

## フロントエンド（React）

### 状態管理・副作用

- useEffect の依存配列が正しいか、クリーンアップ漏れがないか
- 不要な再レンダリング、state の持ち方が適切か

### リアルタイム通信（ActionCable）

- 購読（subscription）の解除漏れがないか（アンマウント時）
- 切断・再接続・エラー時のハンドリングがあるか
- 本人視点の snapshot 配信を正しく扱えているか

### 認証（AuthContext / JWT）

- トークンの保管方法に XSS リスクがないか
- トークン更新・失効（jti 不一致）時の挙動が正しいか

### セキュリティ

- dangerouslySetInnerHTML やユーザー入力由来の XSS リスク
- 機密情報をフロントにハードコードしていないか

### API 通信

- エラー・ローディング・失敗状態を扱っているか
- 競合状態（race condition）がないか

### テスト

- 正常系・異常系がコンポーネントテストでカバーされているか

### コード品質

- `yarn lint`（ESLint）の警告がゼロか
