# 実装計画

着手前に以下を提示し、承認を得てから実装する。
プランモード規約に従い、具体的なコード例は出さず、方針・設計判断のみ示す。
自明な小タスクは簡略可（フル計画は設計判断を含む中〜大タスク向け）。

## 計画に含める項目

- **目的 / 背景**: なぜこの変更が必要か
- **受け入れ条件**: 完了の定義（満たすべき条件）
- **対象 / 対象外**: 変更スコープと、あえてやらないこと
- **設計方針と代替案**: 採用案と、却下した案・その理由
- **DB・API への影響**: マイグレーション要否、API 契約の変更
- **セキュリティ / パフォーマンス**: 想定される懸念
- **テスト方針**: 正常/異常/境界、Rails(Minitest)・React(Vitest) のどちらを書くか
- **段取り**: 実装ステップを詳細に列挙する
  - **順序**: 処理の上流から下流へ並べる（入口・トリガー → 中間処理 → データ層）。実行時の流れに沿わせ、人間が読んで追える順にする
  - **粒度**: 各ステップは、対象の単体テストを併せて書いて green にできる最小単位まで細かく分ける。1ステップ完了ごとに、追加したテストが通り、かつ既存テストを壊さない状態を保つ
  - 上流が未実装の下流に依存する場合は、依存先をモック/スタブして green を保つ（または下流の最小実装を先に置く）
- **PR 分割**: 変更が大きい・複数の関心事に跨る場合、PR の分割案を提示する（各 PR の範囲と順序）。分けない方が良ければ単一 PR とする
- **未決事項 / リスク**: 判断保留中の点、残存リスク

## 永続化

計画が人間に承認されたら、内容を次のファイルに保存する（ブランチ単位、git 追跡対象外＝ローカル作業メモ）:

```
.dev/contexts/<サニタイズ済みブランチ名>.md
```

- `.dev/contexts/` は `.gitignore` 済み。実装者の確認用ローカルメモであり、コミット・共有しない
- 耐久的な設計判断の理由は PR 本文に残す（このファイルには残さない前提で運用する）
- ブランチ名の `/` は `-` に置換する（例: `refactor/claude-config-to-skills` → `refactor-claude-config-to-skills`）
- 承認済みの計画本体を記録する
- 既存ファイルがあれば追記・更新する（別セッションの記録を尊重する）
