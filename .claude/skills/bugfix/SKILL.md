# バグ修正

症状を場当たりに塞がず、再現 → 原因特定 → 最小修正 → 検証の順で進める。

## 手順

1. **再現**: バグを再現する failing test を先に書く（修正前に red を確認）。テスト規約は `stoss-test` に従う（日本語名・Rails(Minitest)/React(Vitest)）
2. **原因特定**: 症状ではなく根本原因を特定する。同じ原因が他の箇所にも波及していないか確認する
3. **最小修正**: 原因に対して最小限の変更で直す。無関係なリファクタや改善を混ぜない
4. **検証**: 1 の再現テストが green になることを確認する
5. **リグレッション**: 全テストを実行し、既存テストを壊していないことを確認する

## 補足

- 自明な修正（typo・文言など挙動を変えないもの）は再現テストを省略可。挙動のバグは必ず再現テストを書く
- 自動再現が難しいバグ（競合・リアルタイム/ActionCable・Redis 状態など）は、最小の自動チェックを試みつつ、手動再現手順を計画/PR に明記する
- 修正中に見つけた別の問題は、混ぜずに別タスク（issue/メモ）として切り出す
