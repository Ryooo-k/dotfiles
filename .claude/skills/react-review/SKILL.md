# React のレビュー観点

手順・重要度・結果の形は `dev-review` skill に従う。ここには React の変更で見る観点だけを書く。

ユーザーはフロントのコードを読んでレビューできない。人間に渡すときは、コードの説明ではなく、画面で何がどう変わるか・どう操作すれば確かめられるか（異常系を含む）・判定をクライアント側に移していないかを書く。

## 状態管理・副作用

- useEffect の依存配列が正しいか、クリーンアップ漏れ（購読・タイマー・イベントリスナー）がないか
- 不要な再レンダリング、state の持ち方（同じ値を 2 か所に持っていないか）が適切か

## 認証

- トークンの保管方法に XSS リスクがないか（localStorage に長く使えるトークンを置かない）
- トークンの更新・失効時の挙動が正しいか

## セキュリティ

- `dangerouslySetInnerHTML` やユーザー入力由来の XSS リスク
- 機密情報をフロントにハードコードしていないか
- 権限・正否の判定をクライアントだけで行っていないか（サーバーでも確かめているか）

## API 通信

- エラー・ローディング・失敗状態を扱っているか
- 競合状態（race condition。古い応答が新しい応答を上書きする、画面を離れた後に state を更新する）がないか

## テスト

- 規約は `react-test` skill に従う
- 正常系・異常系がコンポーネントテストでカバーされているか

## コード品質

- ESLint（`yarn lint` など、プロジェクトの lint コマンド）の警告がゼロか
